# Roadmap

What comes next for OpenDJDecks, in the order it will be built. Numbers in brackets stay the same as items move, so they can be referred to in issues and commits.

The priorities come from 80 simulated expert interviews (UI and UX designers, DJs mostly from electronic music, lighting operators) held in November 2026, each point checked against the code. Simulated interviews give hypotheses, so feedback from real users can change this order.

Two findings set the order. People judge the interface by its hierarchy and finish first, so the design work comes early. And nobody moves their gigs to new software on features alone: they want proof that it holds up, so that proof is part of the plan.

## How each step is built

- One step per pull request, so a release can stop after any step.
- A step is done when its "Done when" is true, tests cover it, English and German text and the guides are updated, and screenshots or clips show the new state.
- Sources and naming follow [CONTRIBUTING.md](../CONTRIBUTING.md).
- Anything that needs hardware stays open until it has been confirmed on that hardware.

## 0.7.0: beautiful, readable and safe at a gig

### Step 1: stem model setup

- [x] **[S1] Guided model download.** Asks before the one-time download, shows progress, explains errors with retry and help, and can start again from nothing in Preferences. Done when an interrupted or damaged download can always be repaired from Preferences, and the guide explains how.

### Step 2: a design language worth looking at

These come first because every later screen builds on them.

- [x] **[44] Surfaces and spacing.** Two or three visible surface levels and one spacing scale, so groups separate without outlines around everything. Keeps the dark base, the deck colours and the platter ring. Needs `DESIGN.md` updated first, because it currently requires outlined plates, square corners and dashed active states. Done when the rules are rewritten and applied to Perform.
- [x] **[4] Plain words.** One glossary applied everywhere: full words such as Keylock where space allows, Stems on the deck, LIGHT and LIGHTING told apart, side rails spelled out. Done when each concept has one name in the app and the guides.
- [x] **[2] One state language.** Off, selected, on, armed, running, disabled and focused as documented tokens, used in Perform, Lighting, FX and Preferences, with a visible focus ring. Each accent colour has one job and colour is never the only cue. Done when dashed outlines no longer mean "selected" and idle toggles never look lit.
- [x] **[43] Type scale.** About five sizes and two weights, fixed-width figures for changing numbers, and BPM and remaining time as the largest values on a deck. Done when hard-coded font sizes are gone.
- [x] **[1] Legibility.** A minimum of 11 px for labels and 12 px for anything read live or touched, with contrast of at least 4.5:1 measured on each surface. The text size setting also scales the deck. Done when no label is below the floor and a test enforces it.
- [x] **[3] Gig preset.** High contrast, colour-blind palette and interface scale can be found near the top bar and in the first run, and combine into one preset. Scale applies without a restart. Done when all of it is reachable in one step.

### Step 3: hierarchy and orientation

- [x] **[5] Top bar in zones.** Modes, panels and status are visibly separate. Recording is red with a timer. Live values are never cut off, and editing actions appear only where editing happens. Done when each element in the bar has a clear kind and state.
- [x] **[8] Three tiers in Perform.** Play, cue, sync and faders dominate, loops and pads form a middle tier, setup keys recede, and empty hot cues are drawn hollow. Done when a deck's state can be read at a glance from arm's length.
- [x] **[7] Guided first start.** A checklist that ticks itself and highlights the real control: add music, wait for analysis, load two tracks, play and sync, with sample tracks and an audio test tone. Done when a new user reaches a first mix without the guides.

### Step 4: nothing goes wrong during a set

- [x] **[10] Audio health and gig check.** A permanent status with device, latency and dropouts, a clear alert when the device is lost, device change without a restart, and a check before the gig for outputs, controller, disk and missing files. Done when unplugging the audio interface is shown at once and can be recovered from.
- [x] **[9] Restore after a crash.** Deck state is saved continuously and offered back after an abnormal exit, and a running recording survives. Done when killing the app mid-set restores tracks and positions and keeps the recording.
- [x] **[11] Performance lock.** Blocks loading onto a playing deck, deleting and grid editing. Keeps the computer awake and pauses background work while decks play. Done when none of these can happen by accident while locked.
- [x] **[12] Phase and tempo between decks.** A phase meter and tempo difference in Perform with a clear in-sync state, and an option to practise without sync. Done when manual beatmatching can be judged from the screen.
- [x] **[58] Booth view.** A large view with two big waveforms and large BPM, key, remaining time and phrase countdown. Done when it is readable from a few metres away.

### Step 5: proof that it holds up

- [x] **[51] Published long-run results.** Sets of 4 to 8 hours with two and four decks, stems, effects and recording on an ordinary laptop, with dropout counts and latency, published where DJs read them. Done when the results are repeatable and linked from the website. Four-hour runs with two and four decks are published in the long-run results guide, with the logs and the command to repeat them. They ran on a computer in daily use; a run on a quiet computer and eight-hour runs are still to come.
- [x] **[52] Hardware status per model and control.** Verified, partial or untested for every mapped control, with a self-test for controls and LEDs before a gig. Done when the list is public.
- [x] **[53] Stick compatibility and check.** A list per player model covering cues, grids, memory points and playlists, and a check of a stick before a gig with a result per track. Done when a stick can be declared ready.

### Step 6: a lighting rig you can trust

- [x] **[14] Patch table.** Universe, address, mode and channel count are editable, with bulk add, collision display and identify. Done when a real rig can be patched without editing files.
- [x] **[16] Output status and failsafe.** Status per universe, also visible in Perform, a live channel view, USB reconnect, and a chosen behaviour for a lost link or crash. Done when pulling the interface is shown and recovers by itself. Loss and recovery are tested with a simulated link; pulling a real USB-DMX interface has not been tried yet.
- [x] **[19] Safety limits.** A strobe rate cap with a safe default, lockout for fog and lasers, level caps per group, and a PIN that keeps guests out of setup. Done when automatic looks cannot exceed the limits.

### Hardware checks

These need the real devices. They do not hold up any release: until one is confirmed, the release notes and guides say it is unconfirmed.

- [ ] **[H1] Controller mappings** confirmed on a real DDJ-FLX10, with unconfirmed entries resolved.
- [ ] **[H2] Club player USB** confirmed on real players, including the WAV conversion for older ones.
- [ ] **[H3] Several sticks at once** and eject confirmed on physical sticks.

## 0.8.0: what electronic DJs need, and it adapts to you

### For the mix

- [x] **[54] A library import people can trust.** A preview of what will carry over before anything is written, then a before and after count, a list of what did not transfer, and undo. Covers documented export formats. No automatic reading of other software's private files. Done for the library XML and Music / iTunes `Library.xml` exports; undo restores a copy taken right before the import and is offered while the result window is open. The preferences import now asks for the folder instead of looking for it.
- [x] **[55] A mixer for bass swaps.** A kill per EQ band, a one-tap and optionally quantised swap between decks, larger EQ and filter with values and double-tap reset, and clip display. Done in the app (the knobs are larger at desktop size only; the mid tier keeps its 16 px knobs to leave the decks their width) and as the mapping actions `mixer.eq_kill` and `eq_swap`; the swap lands within one audio block of the beat or bar. Not tried on a hardware controller or a real touch screen yet (double-tap is the Slint double-click on touch), and no shipped mapping uses the new actions.
- [x] **[56] Phrase-aligned blends.** Bars to the next phrase, breakdown or drop on each deck, phrase-snapped sync, start on the next phrase, and the incoming track drawn over the playing waveform. Done in the app: DROP / BREAK bars on each platter, a right click on PLAY (or `deck.phrase_start`) starts a cued deck on the master's next phrase within one audio block, the PHRASE sync mode jumps a syncing deck whole beats into the same place in its phrase, and the master's lane draws the incoming track's outline. Tested with generated tracks only; not tried at a gig, by ear on a real set, or from a hardware controller, and no shipped mapping uses `deck.phrase_start` yet.
- [x] **[57] High tempos.** Detection up to and beyond 200 BPM without halving, a visible active range, and one-press half and double on the deck. Done: a 150–300 BPM range; generated click, kick, kick-and-snare and house loops at 170, 200, 220, 250 and 280 BPM read as played (within 0.05 BPM) in every range that holds them, and the default 70–180 folds 200 and 220 to 100 and 110. The active range shows in the Prepare player's INFO tab and beside the analysis progress; ÷2 / ×2 sit on the full deck's BPM readout (the GRID panel on narrower decks) and as `deck.bpm_half` / `deck.bpm_double`. Not yet checked on a collection of real records above 200 BPM.
- [x] **[59] Loop roll and loop capture,** quantised from 1/32 beat to 4 beats and shown on the key and waveform. Done as the ROLL pad mode (slip-style: the track goes on underneath and resumes on release, a line on the waveform shows where) with CAPTURE in its mode bar, which stores the loop just heard as a hot loop on the first free pad (a memory loop when the bank is full); also `deck.loop_capture` and the pad mode `loop_roll` in mappings. Not tried on hardware pads yet.
- [x] **[60] Stems ready before the gig.** Separate a whole set ahead of time, show stem state per track and on each key, warn on load, and offer solo and keep-only-this. Done in the app: **Separate stems for the whole list** (row menu, File menu, `⌥⇧⌘P`) queues every track of a playlist or set without stems; an optional STEMS column shows ready, queued, separating and failed (also for tracks a deck separates itself); the stem keys show QUEUED and the progress, and NO STEMS in sodium when a track without stems comes in where stems were in use, with the fix on the status line; right click solos a stem (back as it was on a second right click), ⇧-click keeps only it; also `deck.stem_solo` (held) and `deck.stem_keep`. A deck holding a track the batch finishes takes its stems without a gap. Tested with generated tracks and a mocked model; a whole real set has not been separated end to end for this step, and solo / keep-only have not been tried from a hardware controller.
- [x] **[61] Effects for drops.** Larger controls with visible intensity, a panic off, an XY control, build-ups locked to 8, 16 or 32 bars, and tails after release. Done in the FX panel, which keeps its height: the level as a large percent over a bar you drag; ALL FX OFF (also `⇧Esc` and `fx_panic`) fades every Tempo FX, tail, exit and Hold FX and the channel FX knobs to dry within 5 ms; XY turns a unit into one surface (across the parameter, up the level, played while held); BUILD 8 / 16 / 32 rises to the next bar line of that length on the grid and lets go for the drop (also `tempo_fx.build_up`); TAIL off / echo / reverb rings out after release for effects without a tail of their own. Engine tests render the bar lock, the tails and the panic; not judged by ear at a gig, not tried from a hardware controller, and no shipped mapping uses the new actions yet. With the panel open at 1440×900 the mixer's CH FX caption is clipped as before this step (the panel's height is unchanged).
- [x] **[62] Key relation on the deck,** coloured against the other playing decks, and a confidence value for key and grid analysis with a one-button fix. Done: the deck's KEY is underlined against the other playing decks with the key you hear (key shift, and the tempo without keylock): solid green fits, dashed sodium an energy change, struck deep red a clash, in words on hover; DESIGN.md's own line grammar and wavelengths, no product key colours. The analysis stores how sure it is of key (lead over the runner-up) and grid (beats on a hit, the half / double call) in schema 4; Prepare's INFO tab shows both with USE for the likely key or tempo and ANALYSE AGAIN, and an unsure key shows its percent under the deck's KEY. Tracks analysed before this version show no value until analysed again. The confidence was checked on generated signals only, not yet against a collection of real records.

### For the person


- [x] **[6] Simple, Standard and Full layouts,** with saved layouts. Whole groups can be hidden, and a Simple deck has about 25 controls. Done: the top bar's view menu, **View › Deck Layout** and the first-start guide (from the third step) choose the layout. Simple has 23 large controls on a deck (pads A–H as hot cues, loop and beat jump, SYNC / CUE / PLAY, tempo fader, stems, MASTER) and leaves out the setup keys, the platter, the phase strip and the effects; Standard is the deck as before (compared at 1440 × 900); Full shows every group with the Tempo FX panel open. PADS, LOOPS, STEMS, FX, MIXER, PHASE and SETUP KEYS hide as whole groups, which are then not built at all (a UI test counts the Simple deck's controls and checks that hidden ones cannot be found). Saved layouts are named, switched and deleted in the same menu and kept in the settings. The kiosk and Club mode keep their own decks; Simple and Full have not been tried on a touch screen.
- [x] **[13] Confirmed controller list.** A published matrix with status, more mappings for entry-level and battle-style controllers, and a guided setup for unlisted ones. Done as a controller list in the controllers guide, generated from the mapping files: each model is verified only when every control is confirmed on a unit, and today every row says not confirmed. The guided setup (Preferences › Controller or View › Controller Setup) asks for each core control in turn (play, cue, sync, jog, tempo, load, pads, channel faders, trim and EQ, headphone cue, crossfader, browse, levels), points at the matching control on screen, learns it with MIDI learn and saves a mapping file to share, every entry marked `verify = true`. It starts from generic templates by class (two decks entry level, two decks battle style with the CUT crossfader curve, four decks) in `mappings/templates/`. No new model mapping was derived from manuals, MIDI charts, vendor software or other projects' files: further model mappings, for entry-level and battle-style controllers too, come from owners' own captures through the guided setup, and none of those is confirmed yet. Tested with simulated MIDI only; the setup has not been run with a real controller.
- [x] **[15] Own looks and chases** in a pad grid with live colour preview, flash or latch, pages and group masters, mapped to pads and MIDI. Done as PADS in the LIGHTING view: 4 pages of 8 pads; a look sets program, colour and level per group (the groups it leaves out keep what runs underneath), a chase steps through looks on the beat (a quarter beat to two bars); latch or flash per pad; each pad shows the colours of its look and follows every edit; group masters beside the pads. Looks, chases and group masters are saved with the rig. The deck pads in LIGHTING mode play the current page; the mapping actions `lighting.pad`, `lighting.page(_next/_prev)` and `lighting.group_master` reach them, and MIDI learn fills in the pad, page or group. Tests show a chase cannot exceed the strobe cap. Tested with simulated MIDI only, not from a hardware controller, and no shipped mapping uses the new actions yet.
- [x] **[17] Full lighting controls in Perform and Club,** legible in the dark and sized for touch. Done: STRIP opens a lighting panel in the browser's place in Perform and Club (stage preview from 1360 px, pages and pads, master and group faders, AUTO / EASY / PRO, DMX OUT, HOLD, RELEASE, who is in control, BLACKOUT / FLASH / STROBE / FOG); every key, pad and fader is 44 px or more. A UI test checks that every deck, mixer and waveform element keeps its place and size at 1440 × 900 and 1280 × 800 with the panel open, in Perform and in Club. The browser is hidden while the panel is open. Not tried on a real touch screen yet; the mixer's CH FX caption at 1280 × 800 is clipped as it was before this step.
- [x] **[18] AUTO you can steer.** Palettes, an editable phrase-to-look table, hold and a clear order of AUTO, overrides and release. Done: palettes (track key, warm, cool, sunset, ocean, white, own swatches), a phrase-to-look table for intro, verse, build-up, drop, breakdown and outro (a program or one of your pads), HOLD, and RELEASE that hands back to AUTO over one beat. Who wins, top first: blackout, the FLASH and STROBE keys, a flash pad while held, the latched pad, HOLD, AUTO; a pad takes only the groups its look sets. The order is written in the guide and shown in the view with the layer in control lit, and IN CONTROL names it in the view and the panel. Not yet judged at a gig with real lights.
- [x] **[20] Connecting interfaces.** Several universes, port picker, Art-Net node discovery, test pattern and a short guided setup. Done in OUTPUT: each universe gets its own Art-Net Port-Address or sACN universe unless one is given; PORTS lists USB serial adapters with REFRESH; FIND NODES sends an ArtPoll to the broadcast address and lists the nodes that answer; TEST PATTERN (each, colours, full) replaces the show and passes the safety limits (tests show it cannot exceed the strobe cap); GUIDED SETUP takes four steps and ends with the test. Discovery is tested with a fake node on the loopback address; no real Art-Net node, sACN receiver or USB-DMX interface has been tried with these parts yet.

## 0.9.0: the rest of the craft

### Interface

- [x] **[45]** A motion language: named timings and one curve for press, toggle, panel and mode change, with audio-linked visuals left unsmoothed. Done: four timing tokens (press 90 ms, toggle 140 ms, panel 180 ms, mode change 240 ms) and one curve in the theme; every animation uses them, and a design test fails on any other timing written in the interface or any smoothing of the waveforms, phase meter or booth. **Reduce motion** in Preferences › View sets them all to 0 ms and stills the pulse, the loading sweep and the strobe preview; it starts off, since Slint does not report the system setting. Meters, waveforms, playheads and the phase meter are never smoothed.
- [x] **[46]** Knobs, faders and meters that feel physical: value arcs, centre marks, readouts while dragging. Done: knobs draw a value arc, from a centre mark on bipolar knobs (trim, EQ, filter, FX parameter), and show their value above the ring while dragged; fader caps have grip ridges and a centre line, the tempo fader a centre detent and its tempo beside the cap while dragged; channel and master meters hold their peak. The platter is centred in the deck with SLIP / QUANTIZE / KEYLOCK / range as one block whose inner edges follow the ring, SYNC / CUE / PLAY on the same axis, and the Club keys wrap the jog the same way. Sizes at 1440 × 900 and 1280 × 800 are unchanged (tests). Tried with a mouse only, not on a touch screen or a controller.
- [x] **[47]** Set Flow redrawn as a clear chart, with transition warnings between tracks. Done: per track an energy bar, a dot on a tempo line (with the set's lowest and highest BPM on an axis) and key, BPM, position and start under it; between tracks a marker in the line grammar. A transition warns above 6 % tempo change (half and double time count), on a key clash by the key relation of [62], and on a steep energy drop or jump; each warning is listed under the chart with its reason, and a click on it or its marker selects both tracks. The energy thresholds were set on generated tracks and the demo library, not yet on real sets.
- [x] **[48]** Preferences and the stick screen in the new design, with live previews. Done: Preferences sit on DESIGN.md's surfaces (a panel column for the categories, a band per section, filled choices and switches); the View page opens with a preview of the waveform (colours, calm waveform), the deck colours and status lines (colour-blind palette, contrast), a reading at the chosen scale and a plan of the deck layout, which can now be chosen there. The USB screen gives each stick a row with format badges (CLUB USB, WAV, OPENDJDECKS), its sync state in words beside its line, and SYNC / CHECK / EJECT. Tried with simulated sticks only.
- [x] **[49]** A calmer library table: titles lead, aligned figures, clear loaded and selected states. Done: the title in bone at a heavier weight, the artist and figures second, the rest in bone 3 (4.5:1 kept); figures right-aligned in fixed columns with tabular digits; the selected row filled in plate with its sodium tick; the loaded mark is the deck's line and numeral in the deck colour. The lists column now stops at its content width and clips, so dragging its splitter can no longer push the lists over the table.
- [x] **[50]** A calmer waveform option with a crisp playhead and faint beat lines. Done: **Calm waveform** in Preferences › View (off by default) draws a crisp 1 px playhead with dark rims, faint beat lines and softer band colours. The Perform lanes also put the playhead on the window's centre (the mixer's axis), stand their view keys in one column, and can be dragged: a paused deck scrubs 1:1, a playing deck is nudged by the drag's speed and returns to its tempo (with SLIP, to where it would have been). Dragging is tried with a mouse only.
- [x] **[21]** Lighting split into Setup and Show, with a large blackout and an output test. Done: the narrow-window SETUP / SHOW switch is now the general model. SETUP holds the venue and its files, RIG, OUTPUT and SAFETY beside the floor plan, PATCH and CHANNELS, with TEST (the test pattern, each fixture in turn) one key away in the centre's header; SHOW holds AUTO / EASY / PRO, the master, FLASH / STROBE / FOG / TAP and AUTO's steering in a scrolling column over a 56 px BLACKOUT that stays in view at every window size, beside STAGE, PADS and CUES. An empty rig opens on SETUP, a patched one on SHOW. The show column scrolls by wheel and trackpad only, so the hold keys act on the press; on a touch screen it does not scroll by dragging. Tried with a mouse and in UI tests only.
- [x] **[22]** Clearer browser rails, double-click behaviour and Prepare areas. Done: both rails spell their words where there is room and show a sign with the word as tooltip and accessible name where there is not (no more PASST, VERL or SMPL); double-click and Return load to the free deck (or the LOAD TO deck) in Perform and play the track in the player in Prepare, never pausing it; lists, list and panel strip are separate surfaces. The touch layout shows the signs too, without tooltips.
- [x] **[23]** Help overlay that names every control, also on touch. Done: `F12`, `?` (where no shortcut takes it; in Perform on an English keyboard it taps FX 2) or the **?** key in the top bar show it: every visible control gets a numbered callout on its corner (beside it with a leader line where it does not fit, never over another callout, the list or another control's middle), and a list at the side names each with its shortcut. Names and texts come from the controls' spoken names and tooltips, so they stay in sync. A click or tap explains a control instead of pressing it; the arrows move through the list. Tested headless only.
- [x] **[24]** Touch layout beyond the kiosk, covering the whole deck. Done: **Preferences › View › Touch**, offered once when a touch arrives (winit touch events): touch decks with pads, a loop row and their own waveform, a mixer with knob and legend side by side, stacked FX units, 44 px browser rows and lighting palettes; a test checks every control of Perform (decks, mixer, pads, FX, browser, lighting strip) and Lighting at 44 px or more at 1440 × 900 and 1280 × 800. Below about 1060 px the touch decks leave the mixer to the controller, as the kiosk does; Prepare keeps its desktop keys; no tempo fader on the touch deck. The compact decks of a small window now carry pads and loops and stand in the middle of the height the mixer leaves, the strip beside them gives its legends room. The kiosk is unchanged. Not tried on a real touch screen.
- [x] **[25]** Full keyboard focus, readable screen reader names, and no meaning carried by hue alone. Done: every control is a Tab stop with the focus ring (arrows turn knobs and move faders, Return presses); test ids moved to `accessible-id`, and the spoken name is the keymap title, legend or tooltip with its deck, channel or unit, the description the tooltip with its shortcut. A Tab walk over Prepare, Perform (Standard and Full) and Lighting and a name test guard both. Phrase blocks show their initial where the name does not fit; the other states already had line forms or words. Not tried with a real screen reader.
- [x] **[69]** EDIT IN PREPARE from Perform, with quick fixes in place. Done: **EDIT** in the deck header (under MASTER on the full deck, beside the title on compact and browse decks, a 44 px key on the touch decks where they have room; ⌥⇧⌘D / J / F / H, `deck.edit_in_prepare` on a controller) puts the deck's track in the Prepare player at the deck's position with the PHRASE tab open (the grid while the deck's GRID panel is open). A right-click on the waveform, the phrase strip or the KEY opens phrases, beatgrid, cues, key, gain (a GAIN reading with − / + in the player's INFO), track info or stems, and fixes in place without leaving Perform: the downbeat one beat earlier or later, the phrase boundary nearest the playhead one bar earlier or later, the likely key of [62]; each is one undo step. The decks play on and nothing is loaded again: every edit and every undo (phrases, grid, key, cues, gain, tags) reaches the loaded decks at once, the engine keeping the same audio with the new grid or cues, so phrase countdowns, phrase blends, the lights and the waveforms use it. **BACK TO PERFORM** in the top bar, `Esc`, the mode shortcut or the PERFORM tab return to the same decks and views (open GRID panels stay open); the Prepare layout, section and info panel are put back. Tested headless (UI tests for the propagation and for audio playing on across the switch); not tried on a touch screen or a controller.

### DJ

- [x] **[26]** Visible browser filters, more room for the list, fuzzy search and type-then-Enter to load. Done: active filters show as removable chips over the list; the list header is more compact and the lists column folds to its rail; the search forgives typos, matches across title, artist and album and puts the best matches first; after a click in the list, typing goes to the search, the arrows move through the results and Return loads the top hit (or the row moved to) to the free deck in Perform or the player in Prepare. Deck shortcuts on letters wait while the list has the keys (Esc or a load gives them back). The folded column is not remembered across starts; the search was not timed on a very large library.
- [x] **[27]** Recording for release: editable tracklist, chapter markers, separate voice track, loudness and clip display. Done: **TRACKLIST** on a finished mix opens its entries as time, title and artist to rename, move by time, insert and remove; **EXPORT TEXT** and **EXPORT CUE** write the files next to the recording again and put the chapters into its WAV (cue and label chunks), FLAC (chapter comments) and MP3 copy (ID3 chapter frames). **MARK** sets a chapter marker while recording. **Voice track** in Preferences › Recording writes the MIC input on its own beside the mix, sample for sample aligned (test). The recording panel shows integrated and short-term loudness (EBU R 128), true peak and clips while recording, and every finished mix keeps them, red past −1 dBTP or with clips. The meter matches EBU Tech 3341 case 1 and a gated case; the chapters were read back by our own readers only, not by other editors or podcast players, and the voice track was tested with a generated signal, not a real microphone.
- [x] **[28]** Stick format as a labelled badge, stem state per track, and a one-press emergency stick. Done: a stick's formats are one labelled element (**FORMAT** and a badge per format) on the USB screen, in the emergency result and over a stick's track list; the stick's rows in the tree keep their detail line, because three badges do not fit its width. Browsing a stick, the **STEMS** column says **ON STICK** or **NONE** per track and the list head counts them. **EMERGENCY STICK** (also `⌥⇧⌘E`) copies the open set or list and the tracks on the decks into a new playlist on the plugged-in stick, registering it with Club player USB (WAV for older players) and OpenDJDecks if needed; the key fills with its percent and a band gives the result with **EJECT** or the reason it failed. Tested with simulated sticks (folders) only, not on a physical stick or a club player.
- [x] **[29]** Queue in Perform, requests, do-not-play tags, and auto-play with dead-air warning. Done: **QUEUE** beside the list holds what comes next (**ADD**, move, remove, **LOAD NEXT** to a free deck) and survives a restart; a request typed into it is matched to the library by the fuzzy search, or tied to a track by hand. The do-not-play tag is an ordinary tag value: struck red in the list and the queue, a warning with **UNLOAD** and **KEEP** when loaded, passed over by auto-play. **AUTO-PLAY** keeps a deck cued and mixes into it over a cut or 8, 16 or 32 beats (faders or crossfader, SYNC when both have a grid). When the deck on air has 15, 30 or 60 s left and nothing is cued, a red warning over the foot of the list and in the status band says so, with **LOAD NEXT**. Tested with generated 8-second tracks in the headless engine; auto-play has not been tried at a gig.
- [x] **[30]** EQ kills, crossfader curves on the mixer, cut-in and reverse, split cue. Done: the kill keys of [55] stay on the mixer in every layout, and with **STEM** on they mute the part of their band; the guided controller setup asks for them on all three templates (LOW, MID and HI on two decks, HI and LOW on the battle template, LOW on four decks). A key right of the crossfader's B side draws the curve (constant power, linear, cut) and steps through them, the same setting as Preferences, also as the mapping action `crossfader_curve`. **REV** and **CUT IN** (momentary: the channel is heard as if the crossfader were open on its side) join the platter's key block where six keys fit its height, from 1440 × 900; at 1280 × 800 they are on the controller only (`deck.reverse`, the new `deck.cut_in`). **SPLIT** after the PHONES knobs puts the cue in mono on the left and the master in mono on the right (`split_cue`); an engine test checks both sides with generated signals. Not tried on a hardware controller or at a gig, and the two shipped controller mappings do not use the new actions.
- [x] **[31]** Hot cue edits from Perform, drop markers, phrase-quantized jumps. Done: the **CUE EDIT** pad mode makes a deck's pads pick a hot cue, and a panel beside the list renames, recolours, moves it to the playhead (or stores one there) and deletes it, each a library edit with one undo step that the deck's engine follows at once. **MARK DROP** (in the panel, on the PHRASE pads and as `deck.drop_mark`) sets the drop on the downbeat nearest the playhead and clears it at the mark; it is stored per track (schema 5), drawn on the waveform and the overview, and the phrases every reader gets are split there into build-up and drop, so the drop look, **DROP n** and the phrase pads use it. The **PHRASE** pad mode (and `deck.phrase_jump`) jumps back or on one phrase, to the marked drop, or to the next build-up, drop, breakdown or outro by whole beats, so the phrase start lands on the next downbeat in time; tests check the landing on generated grids. The drop is not written to sticks; nothing was tried at a gig or on a hardware controller.
- [x] **[63]** Search at request speed, a played-tonight mark and bulk tag editing. Done: a keystroke now searches the list and the folded text kept from the last one instead of reading and folding all tracks again, and skips typo distances a letter count rules out. Through the real window on 50 000 generated tracks in a debug build, a keystroke took 646 ms (median) before and 103 ms after (95th percentile 152 ms); the first keystroke after a reload still takes about 0.6 s, and a release build and a real 50 000-track collection were not timed. The played tick says when a track was on air, a **TONIGHT** column shows the time and **Not played tonight** filters them out. With several tracks selected the info panel edits all of them, shows **MIXED** where they differ and undoes the edit in one step, with **Do not play** for the selection.
- [x] **[64]** Larger cue pads with names, per-cue trigger behaviour, and a sampler that stays in view. Done: each hot cue keeps how its pad plays it, **CUE** (as before), **LATCH** (plays on, also from a paused deck), **GATE** (only while held, then back on the cue) or **MOMENTARY** (while held, then the track carries on where it would have been), set in the CUE EDIT panel, stored with the cue and named in the pad's corner; an engine test plays all four. The new **PLATTER** group of the deck layout hides the platter and its keys so the pads take its room and show the cue names in full; the deck keeps its size, the pads in the standard layout do not grow. When Perform runs out of room, the Tempo FX panel or the mix preview gives way, never the sampler. The behaviours are not exported to Club USB sticks, and none of it was tried on a hardware controller or a touch screen.
- [x] **[65]** The planned set in Perform: next track, transition note, and where you stand against the plan. Done: the last set opened in the browser is the plan; a line over the list in Perform shows the set, **ON AIR** n / m for the track you hear, **NEXT** with the next track's title, artist, tempo, key and length, the transition note into it, and where you stand: **ON TIME** within a minute, else **BEHIND** or **AHEAD** by minutes and seconds from the set's planned start and the track lengths, and by positions when the plan expects another track, in the status line grammar (struck **OFF PLAN** when the track on air is not in the set); × hides it until another set is opened. Tried with the demo library and the clock, not at a gig; a set across midnight is counted the short way round and tested only in a unit test.
- [x] **[66]** Stems you can audition, and your own stem files as deck parts. Done: **CUE** in front of the stem keys turns them into picks for the headphones: a filled key plays its stem on its own, at full level even when it is muted on the master, on the headphone cue in place of the channel's CUE, while the master stays the same to the sample (engine `SetStemAudition`, with and without keylock; also `deck.stem_cue`). The Prepare player has a **STEMS** tab doing the same for the track playing in it, with where its stems come from and **SEPARATE**. Your own stem files are the parts of a track when they lie next to it, in a folder named after it (`<track>.stems` and the like) or as `<track> - vocals.wav` and the like (WAV, FLAC, AIFF): vocals, drums and bass are needed, at the track's sample rate and within half a second of its length; they come before separated stems, the strip says **OWN**, the status line names the folder or why the files were not used. Tested with generated parts and files in the engine and the app; the fourth stem stays the track minus the other three (an "other" file is checked but not played), the compact decks have no CUE key (controller only), and nothing was tried with a controller, at a gig or with stems from a real release.
- [x] **[67]** Output routing, an external-mixer mode, split cue on one interface, and clock sync. Done: **Preferences › Audio › ROUTING** puts the master and the headphones on output pairs 1/2 to 7/8 of the device, or the headphones on a second device (fed through a lock-free ring that drops or repeats a frame to follow the clock drift); pairs the device lacks are left out and named under **NOW**. **Mixer: EXTERNAL** sends each deck, as it comes off the deck, to its own pair and bypasses the internal mixer; the mixer column shows **EXTERNAL MIXER** with each deck's outputs in the strips' place, the decks keep their places and sizes at 1440 × 900 and 1280 × 800. **One stereo output** carries split cue (headphones mono left, master mono right) on outputs 1/2. **MIDI clock out** sends 24 pulses a beat from the master deck on its own thread, Start on its next beat, Stop, following tempo changes at once and jumps on the next pulse (MIDI clock only, no network tempo protocol). Engine, device-layer and UI tests render a deck on its own pair, split mono left and right and a stem cue that does not reach the master; the clock is tested for 24 ppqn, tempo changes and its jitter (median under 1 ms on this machine, a scheduler hiccup of up to 30 ms tolerated). Not tried with a real multi-output interface, two real devices, an external mixer or a clock receiver; receiving clock is not built, and with the external mixer the recorder records the master pair only (sampler and microphone).

## 0.10.0: CREATE, a small place to make sounds

A fourth tab next to PREPARE, PERFORM and LIGHTING for the things DJs today do in a separate production program before a set. The main one is playing the next track's melody with a single note taken from the current one. CREATE also has a small drum machine and help with which notes fit. It is deliberately small: no timeline, no piano roll, no plug-ins, no mixing console. The order and scope come from 8 simulated DJ interviews held in November 2026 (club, open format, house producer, beginner, drum and bass, melodic techno, teacher, live hybrid); the concept is in [create.md](create.md).

### Melody from one note

- [ ] **[70]** The CREATE tab: MELODY, DRUMS and THEORY, a result bar, and a slim deck strip so the decks stay in view and keep playing.
- [ ] **[71]** Pick one note on a track's waveform, hear it, and see its pitch as a note and cents, with a correction when the detection is wrong or unsure.
- [ ] **[72]** Pitch the note to every note it needs with a clean start and tail, with a warning on large shifts and a hint to pick another source note.
- [ ] **[73]** Key and scale from the analysis (the other deck's or the next track's key in one press), and the scale's notes on pads and on a keyboard strip, with snap to scale and octaves.
- [ ] **[74]** An arrange strip of up to 32 steps on the master grid, played in or typed as note names, with move and delete.
- [ ] **[75]** Render a new file (the original is never touched) at the chosen tempo with a beat grid and one hot cue per note, as single notes or in melody order, with a check of what club players can take.
- [ ] **[76]** The result goes into a playlist, the library's CREATED list and onto registered sticks through the normal sync.

### Playing it live

- [ ] **[77]** A MELODY pad mode in Perform plays the notes on the deck pads, quantised and in sync, and the notes share the sampler's slots.
- [ ] **[78]** Help with what fits: the scale and chords of a deck's key on the keyboard, a check of a typed melody, and plain-word hints that can be switched off.

### Drum machine

- [ ] **[79]** Built-in synthesised kits with pitch, decay and tone per pad, the same on every platform.
- [ ] **[80]** 16 pads and a 16-step row with swing and half time, following the master tempo, sharing kits and samples with the sampler, and playable from Perform.
- [ ] **[81]** Render a pattern as a bar-exact loop file with a hot cue per sound.

### Finish

- [ ] **[82]** Starter melodies and kits so the first screen is never empty, MIDI keyboard input for notes, and the CREATE guide, German text and media.

Live coding stays out until real users ask for it. Whether rendered files with many hot cues play as intended on club players stays open until it has been tried on real players.
